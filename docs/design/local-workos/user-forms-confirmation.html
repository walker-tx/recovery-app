CancelRevoke all sessions

No typed confirmation for session revocation. Revoke all applies to the user's sessions at execution time, not merely the two shown in an earlier snapshot; concurrent session creation semantics must be explicit. A failed request must not be presented as success.

Small, predictable dialogs

Desktop: centered dialog over the inspector.
Phone: fit the viewport with scrollable content.
Escape/Cancel dismiss before submission; focus returns to the trigger. Prevent duplicate submissions and announce the result.

Proposed defaults
Password users only in this form; no Google/Apple fixture selector. Verification starts off. Ordinary edit changes basic identity fields; password recovery remains a separate explicit action. User deletion gets a stronger confirmation than session revocation.

All displayed data is fictional. Inputs and actions are static illustrations. No passwords are collected. Exact validation, optional profile-field support, and concurrent revocation behavior still require SDK/provider compatibility review.
