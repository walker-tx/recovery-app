Proposed behavior

Sessions: a lightweight cross-user list, not a second inspector. Show reliable session IDs and creation times; add device labels only when real metadata supports them.

Revocation: confirm the selected user/session, then refresh the visible data. No instance-wide revoke action and no bulk-selection toolbar in v1.

Deletion: enter the selected user's email (copy/paste allowed), rather than the generic word “DELETE,” to help confirm the target. The destructive action stays disabled until it matches.

Phone: session rows become stacked entries with their revoke action alongside. The deletion dialog fits the viewport.

Design proposal, synthetic data. Copy and confirmation input are interactive; all service actions, including deletion, remain nonfunctional. No tokens or secrets displayed. Loading, empty, error, stale-response, and pagination behavior must be covered in implementation; no runtime behavior is claimed by these mockups.
